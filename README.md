# UniStudy — Java + XML

Қазақша интерфейсі бар оқу платформасы: Android қолданбасы, Java Spring Boot API және браузерге арналған веб-клиент. Учебный проект с тремя ролями: администратор, преподаватель и студент.

Бұл репозиторийде тек бастапқы код пен жасанды демо бар. Реальная база пользователей, личные данные, учебные оригиналы, пароли, история разработки и готовые APK/JAR не публикуются.

## Құрылымы / Структура

- `android/` — native Android, Java 17 + XML, OkHttp; без WebView и без Kotlin-кода приложения.
- `server/` — Java 17, Spring Boot 3.5.8, SQLite, Argon2id; REST API `/api`.
- `server/src/main/resources/static/` — HTML/CSS/JavaScript клиент, обслуживается тем же сервером.
- `init-demo.ps1` — явное создание новой синтетической базы, без перезаписи существующих файлов.
- `build-server.ps1`, `build-apk.ps1`, `run-server.ps1` — сборка и запуск в Windows.

## Қажетті құралдар / Требования

JDK 17+ для сервера; Android Studio, Android SDK Platform 37 и JDK 25 для текущей Android Gradle-конфигурации (AGP 9.4.1). Android Gradle wrapper использует собственный критерий JVM 25. Минимальная версия устройства — Android 8.0 / API 26. Установите SDK через Android Studio и откройте каталог `android`: IDE создаст локальный `local.properties`, который не коммитится. Для ручной настройки можно задать `ANDROID_HOME`.

Gradle wrapper уже включён; отдельно устанавливать Gradle не требуется. Первая сборка скачивает зависимости и требует интернет. `JAVA_HOME` должен указывать на установленный JDK; машинные пути не зашиты в скрипты. На компьютере с 8 ГБ RAM собирайте сервер и Android последовательно.

## Windows: демоны іске қосу / Запуск демо

В PowerShell из корня репозитория:

```powershell
Copy-Item .env.example .env
.\init-demo.ps1
.\build-server.ps1
.\run-server.ps1
```

Откройте `http://localhost:8000`. Проверка API: `http://localhost:8000/api/health` возвращает `{"status":"ok"}`. Окно сервера оставьте открытым, Ctrl+C останавливает процесс.

Инициализация создаёт `private/unistudy.db`, группу DEMO-101, предмет Java Demo, учебный текст и три аккаунта. Пароли хешируются Argon2id с новой случайной солью при каждом создании базы.

| Рөл / Роль | Логин | Только демонстрационный пароль |
| --- | --- | --- |
| Әкімші / Администратор | `demo-admin` | `DemoAdmin123!` |
| Оқытушы / Преподаватель | `demo-teacher` | `DemoTeacher123!` |
| Студент | `demo-student` | `DemoStudent123!` |

Бұл ашық демо-құпиясөздер. Это общеизвестные демонстрационные учётные данные: используйте их только локально. Сервер по умолчанию слушает 127.0.0.1. Демобаза не предназначена для публичного размещения.

Повторный запуск `init-demo.ps1` завершается отказом, если файл существует, даже если он пуст. Инициализация не запускается автоматически при старте сервера. Для независимого демо укажите новый путь: `.\init-demo.ps1 -DatabasePath C:\temp\new-demo.db`, затем задайте тот же путь в `UNISTUDY_DB` в `.env`. После прерванной инициализации может остаться неполный файл: проверьте его вручную, автоматическое удаление отключено.

## Android APK

```powershell
.\build-apk.ps1
```

Результат: `output/UniStudy.apk` (debug APK для локальной установки). Также можно открыть `android/` в Android Studio и нажать Run. Для эмулятора используйте адрес API `http://10.0.2.2:8000` в настройке сервера на экране входа.

Для физического телефона компьютер и телефон должны быть в одной доверенной Wi-Fi сети. Запустите `.\run-server.ps1 -BindAddress 0.0.0.0`, затем укажите `http://<LAN-IP-компьютера>:8000` в приложении; при необходимости разрешите порт в локальном firewall. Не перенаправляйте этот демо-порт в интернет. HTTP разрешён в debug-манифесте для локальной разработки; для release используйте HTTPS и собственную подпись.

## Linux / macOS

```sh
cd server
sh gradlew demoInit test bootJar --no-daemon
cd ..
UNISTUDY_DB=private/unistudy.db UNISTUDY_STORAGE=storage/files \
  java -Xmx384m -jar server/build/libs/unistudy-server.jar --server.address=127.0.0.1
# Отдельно, после установки Android SDK и JDK:
cd android
sh gradlew :app:assembleDebug :app:testDebugUnitTest
```

`.env` читает только PowerShell-скрипт запуска; при прямом запуске Java задавайте переменные среды самостоятельно. Сервер использует `PORT` (по умолчанию 8000), скрипт Windows использует `SERVER_PORT` или `-Port`.

## Үш рөлді көрсету / Сценарий демонстрации

1. **Администратор:** войдите как `demo-admin`, откройте управление пользователями, группами и предметами. Можно создать преподавателя/студента или одобрить новую регистрацию; назначьте студента в DEMO-101, а преподавателя — на предмет. Создайте занятие в расписании.
2. **Преподаватель:** войдите как `demo-teacher`. Откройте Java Demo, добавьте материал или задание, выберите группу DEMO-101, опубликуйте его. Используйте только собственный тестовый файл. Создайте оценивание в журнале.
3. **Студент:** войдите как `demo-student`, просмотрите опубликованные материалы и расписание, отправьте тестовый ответ на задание. Преподаватель сможет проверить ответ и выставить оценку; студент увидит свою оценку.
4. В веб-клиенте и Android доступны одни и те же данные API. Для переключения ролей выходите из текущего аккаунта. Новая самостоятельная регистрация ожидает одобрения администратора.

Демо не содержит настоящих лекций или вложений. При первом запуске сервер создаёт каталог `storage/files`; новые вложения хранятся там, метаданные — в SQLite.

## Тексеру / Проверки

```powershell
cd server
.\gradlew.bat test --no-daemon
cd ..\android
.\gradlew.bat :app:testDebugUnitTest --no-daemon
```

Серверные тесты используют временную базу. Android unit-тесты проверяют правила URL и валидации. Инструментальные сценарии исходного частного проекта зависели от реальных учебных данных и в публичную версию не включены. Демонстрацию трёх ролей можно повторить вручную по инструкции выше.

## Деректер мен қауіпсіздік / Данные и безопасность

`private/`, `storage/`, `output/`, `.env`, `local.properties`, ключи подписи и сборки исключены через `.gitignore`. В репозиторий включены только два служебных Gradle wrapper JAR. Не добавляйте реальные списки пользователей, пароли, токены или скриншоты с персональными данными. В производственной конфигурации используйте отдельные данные, уникальные пароли и HTTPS; это учебная локальная конфигурация.
